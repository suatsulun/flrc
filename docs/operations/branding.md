# Branding and private report assets

This document separates generic application branding, a school's runtime identity, and confidential report assets. Read this when changing logos, names, report templates or signatures; the frontend visual rules live in the [design system](../design/design-system.md).

## Choose the right layer

| Layer                    | Source                                                                   | Consumers                                                       |
| ------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Generic source branding  | Root `branding/brand.json`, `logo.svg`, optional `favicon.svg`           | Public application defaults generated by `scripts/branding.mjs` |
| Runtime public identity  | Private deployment `branding/public/brand.js`, `logo.svg`, `favicon.svg` | Web container at `/branding/` and `/admin/branding/`            |
| Runtime report identity  | Private deployment `branding/brand.json`, `logo.svg`                     | API/worker through `SCHOOL_BRANDING_DIR`                        |
| Private report layouts   | Private deployment `branding/reports/`                                   | Backend report renderer only                                    |
| Teacher names/signatures | PostgreSQL `users` and report identity audits                            | Admin identity editor and assigned report signers               |

Keep the public checkout generic. Real institution names, domains, personnel and signatures belong only in a private deployment. Runtime overlays avoid rebuilding images ([ADR-054](../adr/054-branding-is-a-runtime-overlay-served-next-to-the-app.md)); private report identities are [ADR-057](../adr/057-private-report-overlays-and-teacher-report-identities.md).

## Generic source changes

`brand.json` requires nonempty `name` and six-digit hex `accentColor`; optional `shortName` falls back to `name`. `logo.svg` is required; a missing `favicon.svg` falls back to it.

```bash
pnpm brand
pnpm brand:check
pnpm brand:test
```

Run from the application root after an intentional generic branding change. The generator writes `branding/generated/brand.css`, both app favicons and HTML metadata, backend report assets, and each app's `public/branding/` files. Do not hand-edit generated files. The colour generator takes the accent's OKLCH hue and uses fixed lightness/chroma for its generated primary colour; do not interpret `accentColor` as a request to reproduce an exact corporate button colour.

## Private runtime overlay

Start from the template's generic `branding/` files. A public `brand.js` sets `window.__FLRC_BRAND__` before the app starts:

```js
(function () {
  var here = document.currentScript && document.currentScript.src;
  window.__FLRC_BRAND__ = {
    name: "Example School",
    shortName: "Example",
    accentColor: "#1c62b6",
    logoUrl: here ? new URL("logo.svg", here).href : null,
  };
  document.title = window.__FLRC_BRAND__.shortName;
})();
```

Backend `brand.json` contains `name` and `accentColor`. Mount the complete folder read-only into API, worker and backup at the configured `SCHOOL_BRANDING_DIR` (template `/srv/branding`). `SCHOOL_NAME` and `SCHOOL_LOGO_PATH` are explicit backend overrides; normally leave them unset so screen/report branding stays aligned.

**Before adding confidential assets**, create `branding/public/` containing only `brand.js`, `logo.svg`, `favicon.svg`, and change the web volume to:

```yaml
- ./branding/public:/srv/branding:ro
```

Keep complete backend mounts unchanged. Caddy independently allowlists those three public filenames, with baked-in generic fallbacks for missing files; mount separation also protects against older image configurations. Never put templates, covers, signatures or principal identities in frontend `public/` directories.

## Report overlay contract

`apps/backend/src/flrc/modules/reports/branding.py` validates `SCHOOL_BRANDING_DIR/reports/config.json`:

```json
{
  "version": 1,
  "templates": { "german_karne": "karne.html", "french_karne": "karne.html" },
  "principals": {
    "primary": {
      "name": "Example Principal",
      "titles": { "en": "Principal" },
      "signature": "principals/primary.png"
    }
  },
  "assets": { "german_cover": "covers/preview.png" },
  "covers": { "german_karne": "covers/cover.pdf" }
}
```

- Template keys are `english_elementary`, `english_middle`, `german_karne`, `french_karne`; custom HTML files live under `reports/templates/` and can extend built-in templates.
- Principal keys are `primary` and `middle`. Images and cover paths are relative to `reports/`; absolute paths, traversal and escaping symlinks are rejected. Missing configured files fail instead of silently substituting identities.
- Images must be PNG/JPEG/SVG and become data URIs. Templates run in a sandbox with autoescaping, strict undefined values and cleared globals. Report resource fetching denies network/local-file access.
- `report_branding.principals`, `report_branding.assets` and `card.teachers` provide report identities. A missing teacher signature stays blank; the system never synthesizes one.
- German/French PDF cover substitution relies on the duplex two-landscape-A4-pages-per-pupil layout; preserve report-face/cover ordering when changing templates.

Edit teacher report names and normalized PNG signatures through the admin teacher editor. Class assignments select report signers. These identities live in database backups, unlike private principal assets and templates, which require a separate private repository/asset backup.

## Apply and check

Deploy the private overlay and restart API/worker/backup even if image tags did not change; the template deploy workflow does this. Through authorized views, inspect screen branding, each affected programme, stage-specific signers, preview and final PDF cover replacement. Check that `/branding/reports/config.json` and `/admin/branding/reports/config.json` return 404. A source-only check cannot prove a mounted deployment is correct.
