# Code review

This is the reviewer-agent checklist; read this when evaluating a diff or preparing a self-review. Report actionable defects with evidence, not speculative preferences.

## Establish the contract

Read root `AGENTS.md`, [conventions](conventions.md), the user request/acceptance criteria, and the affected [architecture](../architecture/overview.md) sections. Trace changed entry points through callers, models, migrations, generated client, UI, fixtures, and tests. Read nearby helpers and relevant [ADRs](../adr/README.md) before proposing another abstraction. The checkout's current code is evidence; older design decisions explain why, not an excuse to preserve obsolete behavior.

For each changed behavior, identify happy, absent/null/empty, unauthorized, locked/archived, concurrent/stale, failure, retry, and deletion cases. Separate observed failures from inferences. Use the [testing guide](testing.md) before executing checks: database tests are destructive and shared. Never invent test results.

## Repository invariants and failure modes

| Area                   | Review questions                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Grade data             | Does `Student.id` remain stable across moves/years? Are grade values keyed by person/column rather than current class? Do version checks reject concurrent writes without clearing unsaved conflicts? Are no-op, zero, null and blank text distinguished correctly?                                                                                                                                                            |
| Audit                  | Does every accepted save keep its batch and old/new values? Are rejected/conflicting cells excluded from applied/audit success? Does undo preserve provenance rather than erase history?                                                                                                                                                                                                                                       |
| Enrollment             | Are numbers scoped to year **and stage**, and stage database-derived? Do roster removal/move/language updates preserve historical grades and other years? Are activation completeness and stage-boundary rollover retained?                                                                                                                                                                                                    |
| Permissions            | Are API dependencies authoritative, not just hidden buttons? School-wide discovery and explicit collaborative save confirmation are intentional ([ADR-071](../adr/071-teachers-see-every-class-assignments-decide-warnings-not.md)); do not reintroduce assignment-only visibility. Validate class/year/column/subject/roster scope and grants at writes. Check coordinator vs administrator and last-active-admin protection. |
| Transactions and locks | Reuse the ADR-080 order: accounts by id, then year, class or ordered enrollments, assignments, actions; fields a save writes key-share by id. Can deletion, account edits, assignment changes, rollover, saves and undo interleave without deadlock or recording post-erasure personal snapshots?                                                                                                                              |
| Migrations             | Additive-first compatibility, explicit constraints, upgrade/downgrade coverage, retained history, no applied-revision rewrite. Do seed/copy/rollover/downgrade accidentally restore forbidden programme columns?                                                                                                                                                                                                               |
| Admin undo             | The action/snapshot and write commit together. Undo is seven days, atomic, refuses changed/invalid current state, and cannot partially restore. Test expired/already-undone/missing/conflicting actions, lock order, session revocation, and rollback. Permanent teacher erasure is **not** an undoable deactivate ([ADR-080](../adr/080-a-deactivated-teacher-can-be-deleted-permanently-their-grade.md)).                    |
| Reports/jobs           | Preserve builder/template/renderer boundaries; large sets are durable background jobs. Check job ownership, ordered output, expiry, bounded memory/parts, progress, failure cleanup, and no personal data in task payloads. Do not trust a successful queue submission as a completed report.                                                                                                                                  |
| Auth/privacy           | Same-origin API, origin checks, HttpOnly Redis sessions, fail-closed school config, active allowlist/domain/subject binding. No tokens in localStorage, no real identities/signatures/grades in public artifacts/logs/telemetry, no production test-auth bypass.                                                                                                                                                               |
| Contract/i18n          | Stable operation IDs, generated client updated, machine codes translated in tr/en/de/fr, interpolation parity, subject-language column names. Turkish UI calls a report column “sütun”, never “alan”.                                                                                                                                                                                                                          |
| Loading/responsiveness | Route map has page-shaped skeleton; first load differs from refresh; errors/empty states remain meaningful. Check 1440 desktop and 390×844 phone, cards instead of sideways desktop tables, overflow, long locales, navigation and panel switching with unsaved work.                                                                                                                                                          |
| Accessibility          | Named buttons/dialogs/inputs; semantic tables/regions; keyboard editing, focus trap/return focus, disabled/pending actions; status announcements; no color-only state.                                                                                                                                                                                                                                                         |
| Tests                  | Would the regression test fail before the fix? Does it assert data/visible effects rather than a tautology? Are mocks typed and complete? Preserve independent browsers for conflicts; include denial and rollback assertions.                                                                                                                                                                                                 |

Read [ADR-075](../adr/075-admin-changes-can-be-undone-for-seven-days-and-conflicts.md), [ADR-081](../adr/081-everything-that-loads-shows-a-skeleton-shaped-like-its.md), and [ADR-082](../adr/082-phones-get-card-layouts-not-sideways-scrolling-tables.md) for these cross-cutting expectations.

## Severity and reporting

| Priority | Meaning                                                                | Example                                                                                                                        |
| -------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| P0       | Immediate, broad catastrophic risk; stop shipping                      | Unauthenticated bulk exposure or a universally destructive migration of school grade history                                   |
| P1       | Serious correctness/security failure requiring urgent correction       | Ordinary save silently overwrites another teacher's grades; admin bypass; irreversible deletion leaks signature snapshots      |
| P2       | Real, bounded defect that should be fixed                              | Undo clobbers a later edit; phone action is unreachable; new route crashes on an empty response; missing locale/error handling |
| P3       | Low-impact defect or maintainability issue with a concrete consequence | Misleading noncritical label or a small unnecessary repeated query outside critical paths                                      |

For each finding: give priority, concise title, smallest useful file/line range, triggering input/state, observed or reasoned failure, and why the change causes it. Distinguish blockers from optional improvements. Report overall correctness and residual untested risks; do not flood the author with duplicate manifestations of one root cause.

## Do not flag

- Personal formatting or architecture preferences already handled by repository tools/conventions.
- Intentional documented behavior: collaborative visibility, subject-language labels, synthetic demo identities, retained historical values, and irreversible permanent account erasure.
- A hypothetical defect without a reachable caller/state or supporting evidence.
- Pre-existing unrelated issues as if introduced by the diff; mention a relevant blocker separately with evidence.
- Generated code style when its source/generator is the real edit point.
- Missing a test framework the repository does not use; ask for behavior coverage through its actual pytest/Playwright paths.
- Smaller symptoms already explained by a stronger root-cause finding.
