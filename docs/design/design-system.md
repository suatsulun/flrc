# Design system

This document covers shared UI tokens, components, responsive layouts and interaction states; read this when adding or changing any teacher or admin screen. UI copy and localization belong in [Writing and translations](writing-and-translations.md).

## Principles and sources

- Reuse `packages/ui`, with deep imports such as `@flrc/ui/components/button`. Both SPAs share one visual system ([ADR-029](../adr/029-one-shared-design-system-in-packages-ui-driven-by-semantic.md)). Do not create a second button, dialog or palette in an app.
- Keep the workspace quiet and content-first: flat page headings, bordered cards, readable data, restrained status colour. Tables fill the available width; do not squeeze them into a decorative centred column.
- Light is **Parchment** (warm paper, slate-brown ink, navy actions); dark is **Graphite** (lifted charcoal, light-key actions). The school accent is not the UI palette ([ADR-040](../adr/040-ui-palette-decoupled-from-the-school-accent-colour.md)).
- Phones need a complete workflow, not a cropped desktop screen. Every desktop row action must remain reachable without sideways scrolling in the default phone view ([ADR-082](../adr/082-phones-get-card-layouts-not-sideways-scrolling-tables.md)).
- Loading is content-shaped, never a blank page or a generic full-screen spinner ([ADR-081](../adr/081-everything-that-loads-shows-a-skeleton-shaped-like-its.md)).

Source files are [theme.css](../../packages/ui/src/styles/theme.css), `packages/ui/src/styles/shadcn.css`, `packages/ui/src/components/*`, `packages/ui/src/hooks/*` and the app-specific page/skeleton compositions. Change the shared source rather than copying its implementation.

## Tokens

### Colour

`packages/ui/src/styles/theme.css` defines every semantic colour in `:root` and redefines it in `.dark`. The `@theme inline` mapping exposes `--color-<name>: var(--<name>)`, so `bg-card`, `text-muted-foreground`, `border-border` and `ring-ring` resolve correctly in both themes. Use semantic utilities, including opacity modifiers such as `bg-muted/40`; do not introduce raw palette colours for a new screen.

The exact light/dark OKLCH values live only in `theme.css`; do not duplicate them in page CSS. New colours must be defined in the light block first and overridden, not introduced, in dark mode. Existing primitive internals contain some raw palette classes; they are not a convention to copy into new pages.

`packages/ui/src/lib/theme.ts` owns `ThemePreference` (`light`, `dark`, `system`), `ResolvedTheme`, `THEME_STORAGE_KEY` (`flrc-theme`), `readThemePreference`, `resolveTheme`, `applyTheme`, `setThemePreference` and `onThemeChange`. `useTheme` exposes the control to React. Keep these and each app's `public/theme-boot.js` consistent: the boot script applies the root class before paint. Do not implement theme detection per page.

## Responsive contract

Tailwind's default breakpoints are `sm` 640 px, `md` 768 px, `lg` 1024 px, `xl` 1280 px and `2xl` 1536 px (40/48/64/80/96 rem). No new per-page phone boundary is needed.

- `packages/ui/src/hooks/use-is-phone.ts` exports `PHONE_MEDIA_QUERY = "(max-width: 767px)"`, `useIsPhone()` and `useMediaQuery(query)`. At 768 px, use the tablet/desktop layout.
- Prefer `md:hidden` and `hidden md:block` for pure presentation. When alternate layouts contain inputs/selects, mount only the active layout with `useIsPhone()`: hidden duplicate controls still exist in the DOM and can break labels, focus and sizing checks.
- The teacher grade-entry screen deliberately differs: `STEPPER_MEDIA_QUERY = "(max-width: 639px)"` in `apps/teacher/src/routes/_auth/classes.$classId.$subject.tsx` opens the one-student `StepperView` below 640 px unless the user explicitly chooses a view. Do not change this to the general 768 px phone threshold.
- Below `md`, touch targets must be at least **40×40 px**. Shared small/icon buttons, segmented choices, native selects and theme choices supply `max-md:` sizing. `Checkbox` keeps a 16 px visual box with an expanded hit area. Give custom controls, file pickers and tightly spaced action links an explicit 40 px minimum; not every primitive automatically has it.

## Screen composition

### Header, context, filters and tables

`AppShell` supplies `<main id="main">` with `w-full min-w-0 space-y-4 px-2 py-3 sm:px-3 lg:px-4`. `apps/admin/src/admin/AdminPage.tsx` returns a fragment containing `PageHeader` and its content, so the shell's spacing applies directly. Use this wrapper rather than repeating heading/layout markup.

1. Put the page title and primary actions in the header; counts/read-only notices belong in `meta`.
2. Use `AcademicContextBar` for year/semester and wrapping filter controls for narrower scopes. Keep controls visible and focused when their dependent region reloads.
3. Use `CardHeader` for section title/actions, then `CardBody > TableScroll > Table` for edge-to-edge data. Do not add `CardContent` padding around a wide table.
4. Preserve readable column widths and sticky identity. A contained scroll viewport, not whole-document horizontal scrolling, is the overflow mechanism ([ADR-045](../adr/045-contained-table-viewports-preserve-readable-columns.md)). Headers stay at least `text-xs` (12 px); do not shrink text to fit. Leave trailing slack where the assessment table pattern needs it.

### Phone layouts

- Teachers/users, audit history and completion rows use `PhoneCardList`: identity/status first, labelled settings/figures second, full-width actions last. Put audit flags in visible badges, not hover-only titles. Wrap long names/comments; emails can use `break-all`.
- Class reports and archive use student cards by default, with the **“Kartlar / Tablo”** (Cards / Table) switch and pinned identity in optional phone table mode. `ClassRosterTable` cards contain selection, school number and second-language controls, not empty grade rows; grades are entered in the teacher app.
- Mount only the chosen grade view using `effectiveView`. Keep every row action in both renderings; share action handlers rather than divergent mutation code.
- The assignment board uses expandable teacher rows and a **“Sınıf ekle”** (Add class) checkbox picker on phones, not mandatory drag-and-drop. Selection uses the same save/undo path as desktop drops and the picker remains open during saves.
- Moving students on phones uses selection plus the existing bulk toolbar and confirmation. Dragging is never the only path to a task.

Representative implementations: `apps/admin/src/routes/_auth/{users,audit,archive,assignments,classes}.tsx`, `apps/admin/src/dashboard/CompletionCard.tsx`, `apps/admin/src/admin/ClassRosterTable.tsx`, and `apps/teacher/src/class-report/class-sheet-table.tsx`.

## State and interaction contract

| State                        | Required presentation and behaviour                                                                                                                                                                                                                                                                                               |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First load                   | Shape the whole page using the app's `page-skeletons.tsx`; include phone cards where the real page uses cards. Do not show empty data or zero counts before the request resolves.                                                                                                                                                 |
| Independently loading region | Skeleton only that region, including dialogs, class pickers and additional list pages. Preserve the header, filters and already usable regions. Do not show old-year data under new-year pickers.                                                                                                                                 |
| Lazy route/session           | `route-pending.tsx` selects a page skeleton by route id. Before session resolution use `AppShellSkeleton`; login has its own shell-free skeleton.                                                                                                                                                                                 |
| Empty                        | Use a specific `EmptyState`, `TableEmpty`, or labelled empty card/list message only after loading ends. Explain absence and offer a relevant next action.                                                                                                                                                                         |
| Error                        | Show translated, actionable failure feedback, not raw API details. Mutations surface an error toast; do not report success or discard unsaved values on failure.                                                                                                                                                                  |
| Pending action               | `Button pending pendingLabel={...}`; preserve button width and disable duplicate submission. Spinners remain appropriate on buttons and running background jobs, not as page-loading replacements.                                                                                                                                |
| Success/undo                 | Specific localized success toast. Admin mutations use `useNotifyDone` in `apps/admin/src/admin/undo-toast.ts`; supply the API `action_id` when present so Undo is offered. The toast lasts 12 seconds; the recorded change remains available through Recent changes for seven days. Never promise Undo for irreversible writes.   |
| Destructive action           | Describe the affected record, scope, what survives and what cannot be recovered. Use `ConfirmDialog` instead of native `confirm()`. Permanent teacher deletion uses a five-second `CountdownConfirmDialog` and solid danger confirmation ([ADR-080](../adr/080-a-deactivated-teacher-can-be-deleted-permanently-their-grade.md)). |
| Navigation with unsaved work | Preserve the router's dirty-grade resolver dialog; browser `beforeunload` remains for leaving/closing the document. Panel switching must respect the relevant exit guard.                                                                                                                                                         |

[ADR-042](../adr/042-pending-work-is-visible-and-class-tabs-are-warmed.md) still governs buttons, toasts, dialogs and bounded sibling prefetch; ADR-081 supersedes its old visible loading pill and generic skeleton. `usePrefetchSiblings` lives in `packages/ui/src/hooks/use-prefetch-siblings.ts`; do not introduce whole-school eager loading as a perceived-performance fix.

## Accessibility and review checklist

Use semantic buttons/links, associated form labels, meaningful page/table/list names and visible focus rings. A tooltip alone is not an accessible name. `Field`/`PhoneCardField` do not automatically wire every ARIA relationship. Keep tab order aligned with reading order; confirm dialogs must return focus to a surviving control. Do not trap keyboard users in a horizontal data viewport; `TableScroll` is intentionally focusable. Active rows and status need more than colour alone.

For every new or changed screen:

- [ ] Reuse semantic tokens and the catalogue above; no new palette, font or parallel primitive.
- [ ] Check a 1440 px desktop and 390×844 phone, both themes, and the 768 px boundary. No document-level horizontal overflow; optional table overflow stays inside its viewport.
- [ ] Preserve every action on phone, ≥40 px touch targets, long names/labels/comments, and wrap-safe filters/actions.
- [ ] Provide shaped first-load and region skeletons; update the route map and page composition. One polite loading announcement, no duplicate live regions.
- [ ] Distinguish loading, empty, error, pending and success; preserve values on failure and offer correct Undo semantics.
- [ ] Confirm dangerous effects, countdown where required, disabled duplicate activation and focus return after rows/dialogs disappear.
- [ ] Check keyboard-only operation, meaningful accessible names, form error associations, non-colour status cues and reduced motion.
- [ ] Add all UI text to all four locales; follow [Writing and translations](writing-and-translations.md), including Turkish casing and subject-language column names.

Do not infer visual correctness from a successful build. Browser checks and the relevant automated coverage are described in [Testing](../development/testing.md).
